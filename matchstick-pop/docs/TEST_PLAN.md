## 6. 重要なテストの意図

| TC | 何を守っているか |
|---|---|
| TC-U24 / TC-U34 | 「2本動かして」と書いた問題が1本で解けてしまう出題ミスの流出防止 |
| TC-U36 | 物理的に不可能な問題（6本で四角2コ）を「解なし」と正しく判定できること |
| TC-U41 / TC-E03 | 数値計算が壊れても図が無言で崩れるだけなので、NaN混入を明示的に検出する |
| TC-U45 | 問題データは外部ファイル。HTML/SVGへの注入を防ぐ |
| TC-U47 | サイズ可変の核。寸法以外が変わっていたら比率保持が壊れている |
| TC-E04 | 検証NGなのにファイルを書いていないこと（刷ってしまう事故の防止） |
| TC-G07 | GUIの静的配信が `dist/gui-output/` の外を読めないこと（パストラバーサル防止） |
| TC-G01〜G06 | GUIがCLIと同じ検証ゲートを通ること。GUI独自の検証ロジックを持たせて二重管理にしないための確認 |
| TC-U53 | Web公開版が完全な文書（`webPageHtml`）と本文断片（`webContent`）で正しく分離されていること。Artifact等「本文だけ埋め込む」用途にも流用できることの裏付け |
| TC-U48 | 分割印刷の格子計算（A0→A3で3行3列）。実際の印刷枚数の見積もりが狂わないこと |
