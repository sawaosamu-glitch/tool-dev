## 1. 目的とスコープ

イベント会場に掲示する「挑戦者求ム／Dr.マッチ棒からの挑戦状!!」形式のPOPを、
問題データから繰り返し生成できるようにする。参照写真のPOPが再現できることを最低要件とする。

### IN SCOPE
- 計算式クイズ（7セグメント表示）と四角クイズの2種類のPOP生成
- A4〜A1・B4〜B1・任意ミリ指定への可変対応
- マッチ棒図のSVG自動描画
- 出題の妥当性（指定本数でちょうど解けること）の自動検証
- スタッフ用の解答一覧
- A0等の大判を、A3/A4など家庭・コンビニで印刷できる用紙サイズに分割して出力する
- ローカル専用のGUI（画面上でサイズ・分割印刷・出力問題を選んで生成）
- Web公開用の1ページ版（レスポンシブ・自己完結HTML、他サーバーへのアップロードを想定）

### OUT OF SCOPE
- 印刷業者向けのCMYK変換・塗り足し付きPDF入稿データ生成（家庭／コンビニ／オンデマンド印刷を前提とする）
- 参加者の解答受付・集計・景品在庫管理
- 斜めのマッチ棒を使うパズル（本システムは縦横のみ）

### DEFER
- 問題の自動生成（現状はソルバーによる検証のみ。生成は人が式を書いて検証する運用）
- 多言語対応

## 2. ステークホルダー

| 役割 | 関心事 |
|---|---|
| 主催者（利用者） | イベントごとに問題を入れ替えて短時間でPOPを刷りたい |
| 会場スタッフ | 参加者の解答が正解か即座に判定したい |
| 参加者 | 遠くからでも問題が読め、実際に解けること |

## 3. 成功指標

| 指標 | 目標 |
|---|---|
| 問題を1問追加してから印刷可能になるまで | 5分以内（JSONに1ブロック追記 → `--check` → ビルド） |
| 出題ミス（解けない・少ない本数で解ける）の流出 | 0件（ビルド時に自動検証し、1件でもあれば中止） |
| 対応用紙サイズ | A4〜A1を含む9規格＋任意ミリ指定 |

## 4. 機能要件

各要件は受入基準（Given-When-Then）とテストIDを持つ。

| ID | 要件 | 受入基準 | 検証 |
|---|---|---|---|
| FR-01 | 問題データからPOPのHTMLを生成する | Given 有効な問題データ / When ビルド / Then 問題数ぶんのHTMLと索引・全ページ・解答が出力される | TC-E01 |
| FR-02 | マッチ棒の図をSVGで自動描画する | Given マッチ棒の位置配列 / When 描画 / Then 1本につき棒と頭が1つずつ描かれる | TC-U40 |
| FR-03 | 計算式を7セグメント表示でマッチ棒に変換する | Given `6+9=7` / When 変換 / Then 19本になり重なりがない | TC-U12, TC-U13 |
| FR-04 | 指定本数で解けるかを検証する | Given `6+9=7` と2本 / When 検証 / Then 解 `6-3=3` が1通り返る | TC-U23, TC-I01 |
| FR-05 | 指定より少ない本数で解ける問題を不合格にする | Given 2本と銘打つ問題 / When 1本で解ける / Then ok=false と理由を返す | TC-U24, TC-U34, TC-I01 |
| FR-06 | 検証に失敗した問題があればビルドを中止する | Given 解けない問題を含むデータ / When ビルド / Then 終了コード1、出力ディレクトリを作らない | TC-E04 |
| FR-07 | 用紙サイズを切り替える | Given `--size A1` / When ビルド / Then `@page size: 594mm 841mm` になる | TC-E02, TC-U46 |
| FR-08 | サイズが変わっても版面の比率を保つ | Given A4とA1 / When 比較 / Then 寸法以外のHTML構造が一致する | TC-U47 |
| FR-09 | 四角の数を数える（大きい正方形も含む） | Given 2x2格子 / When 数える / Then 5個（1x1が4、2x2が1） | TC-U30 |
| FR-10 | 解答一覧を出力する | Given 全問題 / When 生成 / Then 問題図と解答図が並び、移動した棒が色分けされる | TC-U43, TC-E01 |
| FR-11 | 検証のみを行う | Given `--check` / When 実行 / Then 検証結果だけ表示しファイルを書かない | TC-E06 |
| FR-12 | 不正な入力を明示的に拒否する | Given 不明なオプション／不正サイズ／スキーマ違反 / When 実行 / Then 具体的な理由を出して終了コード1 | TC-E05, TC-I04 |

| FR-14 | タイル指定が不要・不正なら拒否する | Given `--tile` が `--size` 以上、または `--tile-overlap` が0未満 / When 実行 / Then 具体的な理由を出して終了コード1 | TC-E09 |

## 5. データ要件

問題データ（`data/quizzes.json`）のスキーマは README とバリデータ（`src/lib/quiz.js`）が正。

| 項目 | 制約 |
|---|---|
| `id` | `/^[A-Z]{2}-\d{3}$/`、ファイル内で一意 |
| `type` | `equation` \| `squares` |
| `moves` | 1〜3の整数 |
| `question` | 非空文字列。`\n` で改行 |
| `expr`（equation） | `0-9 + - =` のみ。`=` を含むこと |
| `start`（squares） | マッチ棒キーの配列。重複不可、格子範囲内 |

## 6. 非機能要件（ISO 25010）

| 特性 | 要件 | 実測 |
|---|---|---|
| 機能適合性 | 収録問題が全て指定本数でちょうど解ける | 8/8問 OK |
| 性能効率性 | 全問ビルド（検証込み）が10秒以内 | 約1秒 |
| 互換性 | Node.js 18以上、外部依存パッケージ0 | 依存0で達成 |
| 使用性 | 印刷手順が画面上に表示され、印刷時には消える | `.note` を `@media print` で非表示 |
| 信頼性 | 検証NG時にファイルを書かない | TC-E04 |
| セキュリティ | 問題データ由来の文字列がHTML/SVGに素通りしない | TC-U45 |
| 保守性 | テストカバレッジ80%以上 | 行98.8% / 分岐92.7% |
| 移植性 | 生成物は単一HTML（外部アセットなし） | CSSインライン、SVGインライン |

## 7. 制約

| ID | 制約 | 根拠 |
|---|---|---|
| CON-01 | Chromeの印刷ダイアログで余白が「デフォルト」でないと `@page size` が無視される | ブラウザ仕様（research_v1 参照）。README と画面上の案内で回避手順を明示 |
| CON-02 | 背景グラフィックOFFでは帯の色が印刷されない | 同上。案内に明記 |
| CON-03 | マッチ棒は縦横のみ。斜めは扱わない | 7セグメント表示と格子モデルの前提。斜めを許すと解の同値判定が破綻する |
| CON-04 | 計算式のスロット数（桁数・記号の位置）は固定 | 「移動」＝総本数不変の定義を保つため。桁の増減は追加であって移動ではない |

## 8. リスクと未決事項

| ID | 内容 | 対応 |
|---|---|---|
| RSK-01 | 大判（A1以上）で家庭用プリンタから直接印刷できない | (a) PDF化して業者入稿、(b) `--tile` でA3/A4等に分割し貼り合わせる、の2通りをREADMEに明記（FR-13） |
| RSK-02 | SQ-002 は解が4通りあり、スタッフが1通りしか知らないと誤判定する | 解答一覧に全通りを掲載し、注意書きを追加 |
| RSK-03 | フォントが端末依存（游ゴシック等がない環境） | 見出しは `textLength` で字送りを強制し、フォントが変わっても版面から溢れない設計とした |
