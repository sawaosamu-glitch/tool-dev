# HARNESS — 決定論センサーと安全装置

## 1. 決定論センサー

| センサー | 実体 | 何を検出するか |
|---|---|---|
| 出題検証 | `solveQuiz`（全列挙） | 解が0通り／少ない本数で解ける／既に正解 |
| 単体・結合・E2E | `npm test`（49件） | 座標・7セグメント・描画・CLIの退行 |
| カバレッジ | `node --test --experimental-test-coverage` | 未検証コードの増加（閾値80%） |
| 生成物健全性 | TC-E03 | `NaN` / `undefined` / 空SVG の混入 |
| 版面同一性 | TC-U47 | サイズ変更時に寸法以外が変わっていないか |

全列挙のため、同じ入力に対する解の個数は常に同じ。センサーは決定論的である。

## 2. 安全ハーネス

| 項目 | 状態 |
|---|---|
| 破壊的操作 | **なし**（削除・上書き前削除を行うコードを持たない） |
| 外部送信 | **なし**（ネットワークアクセスを行わない） |
| 課金 | **なし**（外部APIを使わない） |
| 承認ゲート | `--check` で刷る前に検証のみ実行できる |
| 冪等性 | 同じ入力・同じサイズなら常に同じHTMLを出力する |
| kill switch | 検証NGで即中止。ファイルを1つも書かない |

DRY_RUNの仕組みを別途設けていないのは、**このシステムに不可逆な操作が存在しない**ため。
不可逆なのは「印刷して掲示する」という人間の工程であり、そこへ渡す前段に検証ゲートを置いている。

## 3. 失敗 → 禁止事項への変換ループ

失敗が起きたら `harness/failure_patterns.md` に FP-XXX として記録し、
再発防止に一般化できるものを `CONSTRAINTS.md` の禁止事項へ昇格させる。
