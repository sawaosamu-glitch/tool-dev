# CONSTRAINTS — 不変条件

このファイルに書かれたことは、以後のどの変更でも破ってはならない。

## 1. 出題の正しさ（最優先）

- **検証を通らない問題を出力してはならない。** `solveQuiz` が `ok=false` を返す問題が
  1件でもあれば、ファイルを1つも書かずにビルドを中止する。
- **「N本動かして」の問題は、N-1本以下で解けてはならない。** 少ない本数で解けるものは
  出題ミスとして `solvable-with-fewer-moves` で弾く。
- 検証をスキップする `--no-verify` は、デザイン確認など刷らない用途に限る。
  掲示物を刷る前は必ず検証を通すこと。

## 2. 座標モデル

- マッチ棒の長さは **2 half-unit** で固定。座標は**必ず整数**。
  0.5刻みを導入してはならない（解の同一判定が浮動小数比較になり壊れるため）。
- マッチ棒の同一性は文字列キー（`h:x:y` / `v:x:y`）の完全一致で判定する。
- 「移動」は総本数が変わらない操作のみ。本数が変わる操作は解として扱わない。

## 3. 版面

- 版面の寸法は**すべて `--pw`（ページ幅）の比率**で書く。px直書き・mm直書きを
  `.pop` の内側に持ち込まない（サイズ可変が壊れる）。`.tile-page`/`.tile-canvas` など
  `.pop` の外側にあるページレイアウト用ラッパーはmm直書きでよい（`.frame`と同様、
  版面デザインではなく印刷面の割付なので、この規則の対象外）。
- 大見出しは SVG `<text>` + `textLength` で描く。HTMLテキストに戻すと、
  フォントが異なる端末で版面から溢れる。
- `@media print` で `.note`（画面用の案内）を必ず隠す。

## 3b. 分割印刷（タイル）

- `computeTileGrid` の格子計算は変更しない限り、`stepX = tileW - overlap` /
  `stepY = tileH - overlap` で1タイルずつ版面をずらして切り出す方式を維持する。
  版面がタイル用紙の整数倍でなくても、最後の行・列は版面の外側が白紙になるだけで
  欠けは生じない（`.pop` の外側の背景は印刷時に白 `#FFF` へ強制されるため）。
- `--tile-overlap` はタイル最小寸法未満でなければならない（0以上、かつタイル寸法より小さい）。
- タイル出力の `@page` は常にタイル用紙サイズで固定し、`--pw`/`--ph` は元の版面（poster）
  サイズのまま変えない。版面側のCSS（`.pop`内部の比率）を一切変更せずに分割できるのはこのため。

## 4. 禁止事項

- ファイルの削除・ディレクトリの再帰削除を行うコードを追加しない（出力は書き込みのみ）。
- ネットワークアクセス（外部API・フォント・画像のCDN参照）を追加しない。
  生成物は単一HTMLで自己完結すること。**唯一の例外**は `src/gui-server.js`。
  こちらは `127.0.0.1` だけで待ち受けるローカル専用サーバーで、外部への通信は行わない
  （詳細は4b章）。
- 外部依存パッケージを追加しない。Node.js標準モジュールのみで実装する。
  `gui-server.js` も `http`/`fs`/`path`/`querystring` のみで書く。
- 問題データ由来の文字列を、エスケープせずにHTML/SVGへ埋め込まない。

## 4b. ローカルGUI（`src/gui-server.js`）

- **`127.0.0.1` 以外にbindしない。** `0.0.0.0` や外部インターフェースへの待受を追加しない
  （LAN上の他端末から操作できてしまうと、意図しない生成・上書きの窓口になるため）。
- ロジックを二重化しない。GUIは `src/index.js` の `build(opts)` を呼ぶだけとし、
  出題検証・描画・書き出しのコードをGUI側に複製しない。
- 出力先は `dist/gui-output/` 固定（CLIの既定出力 `dist/` とは別ディレクトリ）とし、
  CLIで作った成果物を上書きしない。
- `/preview/` 配下の静的配信は、`dist/gui-output/` の外を読めないようパス正規化で
  封じ込める（TC-G07で固定）。この境界チェックを緩めない。

## 4c. Web公開用の1ページ版（`webContent`/`webPageHtml`）

- 外部リソース（画像・フォント・スクリプトのCDN参照）を一切読み込まない。
  アップロード先が何であれ、1ファイルだけで完結すること（4章の原則をWeb版にも適用）。
- レスポンシブ化のスケール計算（`transform: scale()`の倍率）は、`.pop`内部のCSS比率
  （`calc(var(--pw) * 係数)`）を一切変更せずに実現する。版面デザインを変えずに
  表示サイズだけを変える、という役割分担を崩さない。
- `webContent` は `<!DOCTYPE>`/`<html>`/`<head>`/`<body>` を含まない本文断片、
  `webPageHtml` はそれを正規の文書に包んだもの。この2関数の責務を混ぜない
  （本文だけを他の器に埋め込みたい用途のために分離してある）。

## 4d. 単一ファイル版（`scripts/build-standalone.js` / `dist/match.html`）

- `src/lib/*.js` のロジックを**書き換えずに**require/module.exportsの行だけ取り除いて連結する。
  match.html用に別実装を書かない（CLI/GUI/match.htmlの3箇所でロジックが食い違う事態を防ぐため）。
  `tests/e2e/standalone.test.js` が「埋め込みロジック＝本家のsrc/lib/*.jsと同じ結果」を
  毎回検証しており、これが崩れたらビルドスクリプトの抽出方法を見直すこと。
- ライブラリのJSソースには `` `<script>${FIT_FRAMES_SCRIPT}</script>` `` のような、
  **JS文字列としての`</script`を含むコード**が存在する（pop.jsのwebContent）。これをそのまま
  `<script>`タグの中に埋め込むと、HTMLパーサーがJS構文を理解せず、その場所でタグが閉じたと
  誤認して以降のスクリプトが本文として扱われてしまう（実際に発生し、`escapeScriptClose`で
  `</script` → `<\/script` に置換して修正した）。埋め込み対象のJSを変更するときは、この
  エスケープ処理を経由すること。
- `dist/match.html` はfetch/XMLHttpRequest/WebSocketを一切呼ばない（TC-S05で固定）。
  ローカルでダブルクリックして使う前提のため、外部通信が必要な機能を足さない。
- 印刷用ページを開くボタンは `window.open('')` ではなく **Blob URL + `<a target="_blank">`**
  を使う。`window.open('')`はポップアップブロッカーの対象になりやすく、実際に検証中
  ブロックされて開けなかった（this session's testing）。ダウンロード系ボタンも同じBlobパターンで統一する。

## 5. 印刷運用（ブラウザ仕様に起因する制約）

- Chromeの印刷ダイアログで**余白を「デフォルト」以外にすると `@page size` が無視される**。
  この手順は README と画面上の案内の両方に必ず残すこと。
- **背景のグラフィックをONにしないと帯の色が出ない。** 同じく両方に残すこと。

## 6. 変更時の手順

1. コードを変えたら `npm test` を通す（76件PASS・カバレッジ80%以上）
2. 問題を足したら `node src/index.js --check` を通す
3. 版面を変えたらブラウザで実際にA3とA1の両方を目視する
4. 仕様が変わったら `docs/SRS.md` と `docs/SDD.md` も更新する（コードだけ直して閉じない）
