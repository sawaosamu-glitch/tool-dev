## 1. コード品質の制約

| ID | 制約 | 根拠 |
|---|---|---|
| C-CODE-001 | 1ファイル500行以下 | 可読性維持。超過時はモジュール分割 |
| C-CODE-002 | 1関数50行以下 | 単一責務原則。超過時は関数分割 |
| C-CODE-003 | 1クラス200行以下 | 肥大化防止 |
| C-CODE-004 | ネスト3階層以下 | 可読性維持。早期リターンで対応 |
| C-CODE-005 | ジョブ作成・状態更新は`asyncio.Lock`で排他制御する（SDD 2章「並行処理」参照）。CPUバウンドな処理（faster-whisper/Ollama呼び出し）は必ず`asyncio.to_thread`でオフロードし、イベントループをブロックしない | SDD ADR-004・Round1レビューF-001/F-005：インメモリ方式のため競合状態・イベントループブロッキングのリスクがある |

## 2. セキュリティの制約

| ID | 制約 | 根拠 |
|---|---|---|
| C-SEC-001 | 外部有料APIキーを一切導入しない。**有料無料を問わず、音声取得・文字起こし・要約のいずれの処理も外部SaaS/クラウドサービス（プロキシ・スクレイピングSaaS等）を経由しない。全処理はローカルプロセス内（faster-whisper/Ollama/localhost）で完結させる。ただし、VoicyURLAdapter（FR-EXT-002/003）が`confirmed=true`時にVoicy本体のAPI（Firebase匿名認証・`vmedia-player-api.voicy.jp`）へ音声取得のために通信することは例外とする（C-AI-009〜011の範囲を超えないことが条件）** | NFR-SEC-001、Q6（課金暴走への懸念）。Round1レビューF-019対応：「無料なら外部サービス可」と読める抜け道を明示的に塞ぐ。SD-ALERT-1対応（2026-08-26）：FR-EXT-002承認時に本項の例外規定が未更新だった矛盾を解消 |
| C-SEC-002 | アップロードファイルの拡張子・サイズ検証を必ず先頭で実施する | FR-DATA-001、OWASP Top 10（信頼できない入力） |
| C-SEC-003 | VoicyURLAdapterが受け付けるURLは`voicy.jp`ドメインのみに限定する（SSRF対策） | FR-EXT-001、任意ホストへのリクエストを防止 |
| C-SEC-004 | 音声内容・文字起こし本文・要約本文はログに出力しない | プライバシー保護（HARNESS.md H5） |
| C-SEC-005 | 依存パッケージの既知脆弱性チェック（`pip-audit`等）を定期実施する | サプライチェーン攻撃防止 |

## 3. データ管理の制約

| ID | 制約 | 根拠 |
|---|---|---|
| C-DATA-001 | `work/`, `output/`, `logs/` は`.gitignore`に含め、コミット対象外にする | 音声・個人的な文字起こし内容の意図しない公開防止 |
| C-DATA-002 | テストデータに実際のVoicyエピソード音声を使わない。自作またはCC0音声のみ使用する | 著作権・利用規約リスク回避（RISK-002） |
| C-DATA-003 | 出力ファイル名にタイムスタンプを含め、既存結果を上書きしない | H3冪等性、データ消失防止 |

## 5. AI（Claude Code）への制約

| ID | 制約 | 根拠 |
|---|---|---|
| C-AI-001 | SRS未記載機能の追加禁止。新機能は必ずSRSに追記→承認後に実装 | スコープクリープ防止 |
| C-AI-002 | テスト削除・改ざん禁止 | FP相当の再発防止原則 |
| C-AI-003 | 50往復超のセッション継続禁止。PROGRESS.mdに状態保存してセッション切替 | session-mgmt.md |
| C-AI-004 | 「完了」宣言はDoD全項目チェック後のみ | 品質ゲート |
| C-AI-005 | force push禁止 | 変更追跡性の確保 |
| C-AI-006 | 本ファイルの無断変更禁止。変更は人間の承認後のみ | 自己改変防止 |
| C-AI-007 | FR-EXT-002（Voicy URL取得）の実装方式を変更する場合、必ずRYGゲート（現在Yellow）を再評価してからコードを変更する。**特に非公開APIエンドポイントの特定・利用（ブラウザ開発者ツールでの通信観察等、リバースエンジニアリング相当の調査を含む）を実装する場合は、着手前に社長へ再確認する（単純なURL取得より踏み込んだ行為のため）** | RISK-001/002/006、黄金ルール#3/#4。Round1レビューF-012対応 |
| C-AI-008 | FR-EXT-002を30日以上使っていない状態から再度使う場合、`docs/compliance_log.md`の最終確認日を確認し、30日を超えていれば使用前にVoicy利用規約を目視確認して記録を追記する | RISK-002、SRS 4章。Round1レビューF-011対応 |
| C-AI-009 | VoicyURLAdapterは**利用者が都度手動で入力した1件のURLのみ**を処理対象とする。チャンネル一覧の自動巡回、複数エピソードの一括取得、バッチ処理・スケジュール実行機能を実装禁止とする | 社長承認の範囲（「対象のURLは私の方で毎回入力します」）を超えないため。F-012解決時の条件 |
| C-AI-010 | VoicyURLAdapterは音声取得前に必ず`is_premium`/`is_paystory`を確認し、いずれか`true`の場合は取得を中止する（FR-EXT-003）。このチェックを迂回・削除するコード変更は禁止 | 有料/プレミアムコンテンツへの不正アクセスを技術的に防止するため（RISK-008） |
| C-AI-011 | Voicyの匿名認証で取得した`idToken`を、実在ユーザーのログイン情報を使った認証に差し替える実装をしない（匿名認証のみを使用する） | 社長承認は匿名・個人利用の範囲。実ユーザー認証情報の取得は範囲外（RISK-002/006） |
