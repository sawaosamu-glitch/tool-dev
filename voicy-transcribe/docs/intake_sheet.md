## 段階質問の回答（P1〜P12から要点のみ）

- P1 目的と成功条件: Voicyのエピソードを聞き返さずにテキストで内容を把握できること。成功条件＝URLを入れてから数分以内に全文テキスト＋要約が得られる。
- P2 利用者と業務フロー: 利用者は社長本人のみ。現状は音声を聞きながら手でメモを取っている。
- P3 スコープ: 下記スコープ表を参照。
- P4 機能要件: (1)URL入力欄 (2)音声取得 (3)文字起こし実行 (4)要約生成 (5)結果表示・保存
- P5 データ: 入力＝VoicyエピソードURL（文字列）。出力＝全文テキスト＋要約（ローカルファイル保存）。個人情報は扱わない想定。
- P6 外部連携: Voicy側の音声取得方法が未確定（Phase 1で規約含め要リサーチ）。文字起こし・要約は無料/ローカル手段を優先しリサーチで確定。
- P7 非機能要件: 同時利用者1名（自分専用）。可用性要件は低い（自分のPCで都度起動）。
- P8 受入基準: VoicyエピソードURLを1本入力→全文テキストと要約がエラーなく生成される。
- P9 テスト: 実際のVoicyエピソードURLで手動E2E確認＋自動テストで異常系（不正URL・非公開回・ネットワーク障害）を検証。
- P10 実装計画: Phase 1リサーチで音声取得・文字起こし・要約の技術選定→設計→実装。
- P11 レビュー計画: nagame-devの非対称レビュー（Codex役/Opus役）をPhase 5で実施。
- P12 最終文書化: SRS/SDD/TEST_PLAN/E2E/CLAUDE.md/CONSTRAINTS.mdを作成。

## スコープ表

### IN SCOPE（MVP対象）
- [x] 音声ファイルの手動アップロード（ローカルWeb UI）
- [x] VoicyエピソードURLの入力欄（実験的機能、Should優先度）
- [x] 音声からの文字起こし（全文テキスト、無料/ローカル：faster-whisper）
- [x] AIによる要約生成（無料/ローカル：Ollama+Qwen3）
- [x] 結果のブラウザ表示＋ローカルファイル保存

### OUT OF SCOPE（対象外）
- 話者分離（複数話者の識別）
- 複数ユーザー対応・認証・クラウド公開
- Voicyや他サービスへの自動投稿・自動公開
- モバイルアプリ化

### DEFER（延期）
- 話者分離
- 文字起こし結果の検索・履歴管理の高度化
- 精度向上のための有料APIオプション追加
