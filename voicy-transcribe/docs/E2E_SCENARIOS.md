# E2Eシナリオ — voicy-transcribe

必須6シナリオ + Voicy URL系4シナリオ（計10件。Round1レビューでE2E-08を追加、技術スパイク確定後にE2E-07を正常系に更新しE2E-07b/09を追加）。各シナリオは7項目テンプレートで記述する。

---

### E2E-01: 標準的な音声ファイルで正常処理（正常系1）

1. **前提条件**: サーバー起動済み、Ollama起動済み
2. **入力データ**: `tests/fixtures/standard_5min.mp3`（日本語音声、約5分）
3. **実行手順**: WebUIでファイルを選択→実行ボタン押下→`GET /api/jobs/{id}`をポーリング
4. **期待結果**: 状態が`done`になり、全文テキストと要約が画面表示され、`output/`にMarkdownファイルが生成される
5. **検証方法**: レスポンスJSONの`status=="done"`、`transcript_text`が非空、出力ファイルの存在確認
6. **タイムアウト**: 600秒（NFR-PERF-001の余裕を見た値）
7. **クリーンアップ**: `work/`, `output/`のテスト生成物を削除

### E2E-02: 最小入力（数秒の短い音声）で正常処理（正常系2）

1. **前提条件**: サーバー起動済み、Ollama起動済み
2. **入力データ**: `tests/fixtures/short_3sec.wav`（3秒の短い音声）
3. **実行手順**: E2E-01と同様
4. **期待結果**: 文字起こしは短い全文が生成される。全文が50文字未満のため要約はスキップされ「要約するには本文が短すぎます」と表示される（FR-DATA-003例外）
5. **検証方法**: `status=="done"`、`summary_text is None`かつ画面にスキップ理由が表示される
6. **タイムアウト**: 60秒
7. **クリーンアップ**: 同上

### E2E-03: 最大入力（長時間音声）で正常処理（正常系3）

1. **前提条件**: サーバー起動済み、Ollama起動済み
2. **入力データ**: `tests/fixtures/long_60min.mp3`（約60分、500MB未満）
3. **実行手順**: E2E-01と同様
4. **期待結果**: 全文テキストは必ず生成される。要約はチャンク分割要約が完走すれば生成され、途中でタイムアウト・接続エラーが発生した場合はSDD「長時間音声の要約設計」の縮退仕様に従い、部分要約または`summary_text=None`（要約なし）となる。**いずれの結果でも`status=="done"`でありPASSとする**（Round1レビューF-003対応：要約成功を必須にしない）
5. **検証方法**: `status=="done"`、`transcript_text`が非空、処理時間がNFR-PERF-001の目安（10分音声=15分以内）から按分した妥当な範囲内であることをログで確認
6. **タイムアウト**: 5400秒（90分）
7. **クリーンアップ**: 同上

### E2E-04: Ollama未起動時の異常系（異常系1・外部障害）

1. **前提条件**: サーバー起動済み、**Ollamaは停止**
2. **入力データ**: `tests/fixtures/standard_5min.mp3`
3. **実行手順**: E2E-01と同様
4. **期待結果**: 文字起こしは正常完了し、要約のみ失敗。「要約エンジン（Ollama）に接続できません」が表示されるが、全文テキストは表示・保存される
5. **検証方法**: `status=="done"`（errorにはならない）、`summary_text is None`、`transcript_text`は非空
6. **タイムアウト**: 300秒
7. **クリーンアップ**: 同上。テスト後にOllamaを再起動する

### E2E-05: 不正な入力ファイルでのバリデーションエラー（異常系2）

1. **前提条件**: サーバー起動済み
2. **入力データ**: `tests/fixtures/invalid.mov`（対応外拡張子）
3. **実行手順**: WebUIでファイルを選択→実行ボタン押下
4. **期待結果**: アップロード時点で「対応していない形式です（mp3/m4a/wavのみ対応）」とエラー表示され、ジョブは作成されない
5. **検証方法**: `POST /api/jobs`が400を返す、レスポンスにエラーメッセージが含まれる
6. **タイムアウト**: 5秒
7. **クリーンアップ**: 不要（ファイルは保存されない）

### E2E-06: ファイルサイズ境界値（境界系）

1. **前提条件**: サーバー起動済み
2. **入力データ**: ちょうど500MBのダミーファイル（ランダムバイト列で可、実音声である必要はない）と、500MB+1バイトのファイル
3. **実行手順**: それぞれをアップロードする。**本シナリオはアップロード時点のバリデーション（FR-DATA-001）のみを検証範囲とし、後続の文字起こし処理までは実行しない**（Round1レビューF-016対応：検証範囲を明確化）
4. **期待結果**: 500MBちょうどは受理されジョブが作成される（ジョブは作成直後にテストとしてはキャンセルしてよい）。500MB+1バイトは「ファイルサイズが上限（500MB）を超えています」で拒否される
5. **検証方法**: 境界値それぞれでの`POST /api/jobs`のHTTPステータスコードとエラーメッセージ確認（文字起こし結果は検証しない）
6. **タイムアウト**: 30秒
7. **クリーンアップ**: 生成物削除

### E2E-07: Voicy URL入力から文字起こしまでの正常系（技術スパイクで確定した主要機能）

1. **前提条件**: サーバー起動済み、Ollama起動済み。技術スパイクで確認済みの無料公開エピソードURLを使用
2. **入力データ**: `https://voicy.jp/channel/941/7892642`（無料公開エピソード）、`confirmed=true`
3. **実行手順**: WebUIのURL欄にURLを入力し、確認表示にOKを押して実行
4. **期待結果**: Firebase匿名認証→メタデータ取得→HLS音声DL→文字起こし→要約が実行され、`status=="done"`になる
5. **検証方法**: `status=="done"`、`transcript_text`が非空
6. **タイムアウト**: 600秒
7. **クリーンアップ**: `work/`, `output/`のテスト生成物を削除

### E2E-07b: Voicy URL取得失敗時の手動アップロードへのフォールバック

1. **前提条件**: サーバー起動済み。VoicyのメタデータAPIが障害・仕様変更等で失敗する状態をモックで再現する
2. **入力データ**: 有効な形式のVoicy URL、`confirmed=true`
3. **実行手順**: WebUIのURL欄にURLを入力して実行
4. **期待結果**: 取得失敗時、状態が`fallback_required`になり「Voicy URLからの自動取得に失敗しました。音声ファイルを手動でアップロードしてください」と表示される。MVP機能（手動アップロード）は影響を受けない
5. **検証方法**: `status=="fallback_required"`、UIにフォールバック案内文言が表示される
6. **タイムアウト**: 60秒
7. **クリーンアップ**: 不要

### E2E-09: プレミアム/有料コンテンツの取得拒否

1. **前提条件**: サーバー起動済み。メタデータAPIのレスポンスを`is_premium=true`にモック
2. **入力データ**: 有効な形式のVoicy URL（プレミアムエピソードを想定）、`confirmed=true`
3. **実行手順**: WebUIのURL欄にURLを入力して実行
4. **期待結果**: 「このエピソードは有料/プレミアムコンテンツのため自動取得に対応していません。音声ファイルを手動でアップロードしてください」と表示される。HLS音声のダウンロードは一切発生しない
5. **検証方法**: モックのネットワーク呼び出し回数でHLS取得が0回であることを確認
6. **タイムアウト**: 30秒
7. **クリーンアップ**: 不要

### E2E-08: 未確認でのVoicy URL取得はサーバー側で拒否される（Round1レビューF-002対応・追加シナリオ）

1. **前提条件**: サーバー起動済み
2. **入力データ**: 有効な形式のVoicy URL、ただし`confirmed`を`false`または未指定で送信
3. **実行手順**: UIを経由せず`POST /api/jobs`を直接呼び出す（`{"url": "...", "confirmed": false}`）
4. **期待結果**: HTTP 400が返り、ジョブは作成されない。Voicyへのネットワークアクセスが一切発生しない
5. **検証方法**: レスポンスステータス確認、通信ログ（またはモック）でVoicyへのリクエストが送信されていないことを確認
6. **タイムアウト**: 10秒
7. **クリーンアップ**: 不要

## RYG判定基準

| 色 | 条件 | 次のアクション |
|---|---|---|
| Green | E2E-01〜05, 07, 07b, 08, 09が全PASS | Phase 7（検証）へ進む |
| Yellow | E2E-06（境界値）のみFAIL | 修正して再テスト、Phase 7へは進める |
| Red | E2E-01〜05, 07, 07b, 08, 09のいずれかFAIL | 修正必須、Phase 7へ進めない |

E2E-07はVoicy URL機能自体がYellow運用（実験的機能）のため、失敗（＝取得できずフォールバックする）こと自体は許容される。「フォールバックが正しく動くか」がPASS/FAILの基準であり、「URL取得自体が成功するか」はPASS/FAILの基準にしない。
