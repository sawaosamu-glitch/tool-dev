## 1. はじめに

### 1.1 目的
Voicyのエピソード音声（または手動で用意した音声ファイル）を、ローカル環境で文字起こし・要約し、聞き返さずに内容を把握できるようにする。

### 1.2 範囲
自分専用のローカルWebアプリケーション。外部への公開・多人数利用・自動投稿は範囲外。

### 1.3 用語集

| 用語 | 定義 |
|---|---|
| 文字起こし | 音声データを全文テキストに変換する処理 |
| 要約 | 文字起こしテキストをAIが短くまとめた文章 |
| MVP | Minimum Viable Product。最小限の完成形 |
| 実験的機能 | 動作を保証しないが実装を試みる機能（Voicy URL自動取得） |

### 1.4 参考文書
- `research/research_v1.md`
- `research/research_v2.md`
- `docs/intake_sheet.md`

## 2. システム概要

音声ファイル（アップロードまたはVoicy URLからの取得）を入力とし、ローカルで動作するfaster-whisperで文字起こし、Ollama+Qwen3で要約し、結果をブラウザに表示・ローカル保存するシステム。

```
[ブラウザUI]
   │ 音声ファイル or Voicy URL
   ▼
[FastAPIバックエンド]
   │
   ├─ 音声取得アダプタ（手動アップロード / Voicy URL実験的取得）
   ▼
[faster-whisper（文字起こし）]
   ▼
[Ollama + Qwen3（要約）]
   ▼
[結果表示 + ローカルファイル保存]
```

## 4. 運用サイクル

- 都度起動: 利用者がローカルでサーバーを起動し、ブラウザでアクセスして都度利用する（常駐サービスではない）
- 定期タスク: なし（個人利用のため）
- **Voicy規約の定期確認ルール（Round1レビューF-011対応、具体化）**:
  1. FR-EXT-002（Voicy URL取得）を直近30日以内に一度も使っていない場合、次に使う前に `https://voicy.jp/terms-of-service` を目視確認する
  2. 確認したら `docs/compliance_log.md` に確認日を1行追記する（例: `2026-08-25: 確認、問題なし`）
  3. 規約に自動取得・スクレイピング禁止の明記を見つけた場合、即座にFR-EXT-002の利用を停止し、CONSTRAINTS.mdの採用停止基準に従う

## 6. 外部インターフェース

| # | インターフェース | 方向 | 内容 |
|---|---|---|---|
| EXT-1 | ブラウザUI（HTTP） | 利用者⇄システム | 音声ファイルアップロード / URL入力 / 結果表示 |
| EXT-2 | ローカルファイルシステム | システム→ディスク | 文字起こし・要約結果の保存 |
| EXT-3 | Voicy Webサイト（実験的） | システム→Voicy | URLからの音声データ取得試行（RISK-001/002対象） |
| EXT-4 | Ollama ローカルHTTP API（localhost） | システム⇄Ollama | 要約リクエスト/レスポンス |

外部有料APIは存在しない（faster-whisper/Ollamaはローカル実行）。ただしEXT-3（Voicy取得、confirmed=true時のみ・CONSTRAINTS.md C-AI-009〜011の範囲内）は例外で、Firebase匿名認証および`vmedia-player-api.voicy.jp`への通信が発生する。生成データ（文字起こし・要約結果）自体は外部送信されずローカルにのみ保存される（NFR-SEC-001）。

### EXT-4 詳細（Ollama連携）

| 項目 | 内容 |
|---|---|
| エンドポイント | `http://localhost:11434/api/generate`（Ollama標準ポート） |
| モデル名 | 環境変数 `OLLAMA_MODEL`（既定値: `qwen3:8b`。CPU実行を前提とした現実的なサイズを明示。Round1レビューF-018対応） |
| タイムアウト | チャンクごとに120秒。超過時はFR-DATA-003の例外処理（要約スキップ）に従う（SDD.md「長時間音声の要約設計」参照） |
| リトライ | 接続失敗時は1回リトライ後に例外処理へ移行 |
| レート制限 | ローカル実行のためなし |

### EXT-3 詳細（Voicy連携・実験的）

| 項目 | 内容 |
|---|---|
| 現状 | 公式の第三者向けAPIはなし。旧非公式API(`vmw.api.voicy.jp`)はDNS解決不可で廃止確認済み。現行のWeb版が使う内部API(`vmedia-player-api.voicy.jp`)を技術スパイクで特定済み（research_v2.md「技術スパイク結果」参照） |
| 実装方針 | Firebase匿名認証→メタデータAPI取得→HLS音声DL・結合（SDD.md参照）。取得アダプタとして分離実装し、取得失敗時はFR-DATA-001（手動アップロード）へ自動フォールバックする |
| 運用ルール | 個人利用限定。利用者が都度手動で入力した1件のURLのみを対象とする（バッチ・自動巡回は実装しない、CONSTRAINTS.md C-AI-009）。実行前に確認表示を行い、`confirmed=true`をAPIに渡す（RISK-002対策）。有料/プレミアムコンテンツは取得しない（FR-EXT-003） |
| **技術スパイクの承認範囲（Round1レビューF-012対応、解決済み）** | 社長より、非公開APIの調査・利用を「対象URLは毎回自分で入力する」という条件付きで承認済み（2026-08-25）。この条件をCONSTRAINTS.md C-AI-009として明文化した |

## 7. 機能要件

### FR-DATA-001: 音声ファイルをアップロードする

- **優先度**: Must
- **Given**: 利用者がmp3/m4a/wav形式の音声ファイル（1ファイルあたり500MB以下）を用意している
- **When**: ブラウザのアップロード欄にファイルを指定し、実行ボタンを押す
- **Then**:
  - ファイルがローカルの作業ディレクトリに保存される
  - 後続の文字起こし処理が開始される
- **例外**:
  - 対応外の拡張子の場合、「対応していない形式です（mp3/m4a/wavのみ対応）」とエラー表示する
  - 500MB超の場合、「ファイルサイズが上限（500MB）を超えています」とエラー表示する

### FR-DATA-002: 音声を文字起こしする

- **優先度**: Must
- **Given**: FR-DATA-001またはFR-EXT-002で音声ファイルが取得済みである
- **When**: 文字起こし処理が開始される
- **Then**:
  - faster-whisperにより全文テキストが生成される
  - 処理中は進捗（処理中である旨）がブラウザに表示される
- **例外**:
  - 音声ファイルが破損している場合、「音声ファイルを読み込めませんでした」とエラー表示し、処理を中断する
  - 無音・長さ0秒の場合、「音声データが検出されませんでした」と表示する

### FR-DATA-002-b: 文字起こしの速度/精度を選択する

- **優先度**: Should
- **Given**: 利用者が実行前の画面にいる
- **When**: 「速い」「標準」「高精度」の3段階から1つを選び、実行ボタンを押す
- **Then**:
  - 選択した段階に応じたfaster-whisperモデルサイズで文字起こしが実行される（速い=base、標準=small、高精度=medium）
  - 未選択時は「標準」が既定値として使われる
- **備考**: NFR-PERF-001（10分音声を15分以内）はこれまで通り「高精度（medium）」構成を基準として測定する。CPU向けにcompute_type=int8を用いて高速化する（2026-08-26追加、ユーザー要望）

### FR-DATA-003: 文字起こし結果を要約する

- **優先度**: Must
- **Given**: FR-DATA-002が完了し全文テキストが存在する
- **When**: 要約処理が開始される
- **Then**:
  - Ollama経由でQwen3が全文テキストを要約する。単なる短縮ではなく「話の要点」「今後のビジネス・行動のヒント」「その他メモ」の3見出しに構成する（2026-08-27改訂、ユーザー要望：行動指針として活用したい）
  - 要約結果が全文テキストと合わせて保持される
- **例外**:
  - Ollamaサーバーが起動していない場合、「要約エンジン（Ollama）に接続できません。ターミナルで `ollama serve` を実行してから、もう一度お試しください」と具体的な操作手順つきでエラー表示し、全文テキストの表示は継続する（要約失敗が文字起こし結果表示を妨げない。Round1レビューF-013対応：非エンジニアでも対処できる文言にする）
  - 全文テキストが50文字未満の場合、要約をスキップし「要約するには本文が短すぎます」と表示する

### FR-DATA-004: 結果を画面に表示する

- **優先度**: Must
- **Given**: FR-DATA-002/003が完了している
- **When**: 処理完了後
- **Then**: ブラウザ画面に全文テキストと要約が表示される
- **備考**: 要約・全文テキストそれぞれに「コピー」ボタンを設け、ワンクリックでクリップボードにコピーできる（2026-08-27追加、ユーザー要望：外部ツールで別管理するため）

### FR-DATA-005: 結果をローカルファイルに保存する

- **優先度**: Must
- **Given**: FR-DATA-002/003が完了している
- **When**: 処理完了時
- **Then**:
  - 全文テキストと要約が `output/{タイムスタンプ}_{元ファイル名}.md` としてローカル保存される
  - 保存先パスが画面に表示される
- **例外**:
  - 保存先ディレクトリへの書き込みに失敗した場合、「結果の保存に失敗しました」と表示するが、画面表示（FR-DATA-004）は維持する

### FR-DATA-006: （廃止済み）要約をアイデアログに蓄積する

2026-08-27に新設したが、同日中にユーザーより「要約は別で管理していくので蓄積しなくてよい」との方針変更があり、実装ごと削除した（コードはコミット前のため履歴には残らない）。要約は引き続きFR-DATA-004で画面表示、FR-DATA-005でエピソードごとに個別保存される。

### FR-EXT-001: Voicy URLを入力する

- **優先度**: Must（技術スパイクで実装方式が確定したため、Round1レビュー後にShouldから格上げ。社長より「URLを入れたら文字になる」が本来の主目的との回答を受け、当初のMVPイメージ通りに正式機能として位置付ける）
- **Given**: 利用者がVoicyのエピソードURL（`https://voicy.jp/channel/*` 形式）を持っている
- **When**: URL入力欄にURLを貼り付け、実行ボタンを押す
- **Then**: システムがFR-EXT-002の音声取得処理を開始する
- **例外**:
  - URL形式が `voicy.jp` ドメインでない場合、「Voicyのエピソードページのみ対応しています」とエラー表示する

### FR-EXT-002: VoicyのURLから音声データを取得する

- **優先度**: Must（技術スパイクで実装方式確定。research_v2.md「技術スパイク結果」参照）
- **Given**: FR-EXT-001でURLが受理されている
- **When**: 利用者が「個人利用の範囲でVoicyから音声データを取得します」という確認表示にOKを押し、システムが `confirmed=true` を伴って音声取得処理を実行する
- **Then**:
  - システムはFirebase匿名認証でidTokenを取得し、Voicyのメタデータ API（`vmedia-player-api.voicy.jp`）からエピソード情報を取得する
  - `is_premium`/`is_paystory`が共に`false`（無料コンテンツ）の場合、`chapters[].voice.file`のHLS音声を取得・結合し、FR-DATA-002以降の処理に進む
  - `confirmed` フラグはUI表示だけでなくAPIリクエストの必須パラメータとし、サーバー側で強制する（UIを経由しないAPI直呼び出しでは取得処理が開始できないようにする。Round1レビューF-002対応）
- **例外**:
  - `confirmed=false`（未確認）でリクエストされた場合、システムはVoicyへのアクセスを一切行わずHTTP 400エラーを返す
  - FR-EXT-003（プレミアムコンテンツの場合）に該当する場合はそちらの仕様に従う
  - Voicy側のAPI仕様変更・障害等により取得に失敗した場合は「Voicy URLからの自動取得に失敗しました。音声ファイルを手動でアップロードしてください」と表示し、FR-DATA-001の手動アップロード導線を案内する（フォールバックは維持し、外部サービスの変化に対する耐性を持たせる）

### FR-EXT-003: プレミアム/有料コンテンツの取得を拒否する

- **優先度**: Must
- **Given**: FR-EXT-002でVoicyのメタデータを取得済みである
- **When**: 取得したメタデータの`is_premium`または`is_paystory`が`true`である
- **Then**: 音声取得を中止し、「このエピソードは有料/プレミアムコンテンツのため自動取得に対応していません。音声ファイルを手動でアップロードしてください」と表示する
- **例外**: なし（本要件自体が例外処理）

### FR-SYS-001: 処理の進捗状況を表示する

- **優先度**: Should
- **Given**: 文字起こし・要約処理が実行中である
- **When**: 各処理ステップが開始・完了する
- **Then**: 「音声取得中」「文字起こし中」「要約中」「完了」のいずれかの状態がブラウザに表示される

## 9. データ要件

### DATA-001: 音声入力ファイル
- 形式: mp3 / m4a / wav
- 保存場所: `work/` （処理用一時ディレクトリ、処理完了後も保持。手動削除可）
- ライフサイクル: 自動削除なし（個人利用のため利用者が手動管理）

### DATA-002: 文字起こし・要約結果
- 形式: Markdown（`output/{タイムスタンプ}_{元ファイル名}.md`）
- 内容: メタ情報（処理日時、入力元）、要約、全文テキスト
- ライフサイクル: 自動削除なし
- バックアップ: 対象外（個人のローカルファイルのため）

個人情報・秘密情報は原則として扱わない（音声内容に個人情報が含まれる可能性はあるが、外部送信されないためリスクは限定的）。

## 10. 非機能要件（ISO 25010）

| # | 品質特性 | 要件 | 測定方法 |
|---|---|---|---|
| NFR-FUNC-001 | 機能適合性 | サンプル3エピソードでの目視確認で、固有名詞・数字を除く文の8割以上が意味の通る形で文字起こしされること | 手動確認（受入テスト） |
| NFR-PERF-001 | 性能効率性 | mediumモデル・CPU実行時、10分の音声を15分以内に文字起こしできること（real-time factor 1.5以下） | 実測（E2Eテスト） |
| NFR-COMP-001 | 互換性 | Python 3.9以上、macOS/Linuxで動作すること（Windowsは対象外・Later）。Phase6実機検証で、開発機にPython 3.11+が入っていないことが判明したため、要件をPython 3.9+に修正した（実装済みコードで動作確認済み） | 動作確認 |
| NFR-USE-001 | 使用性 | 初回起動から結果表示までの操作は3ステップ以内（ファイル選択→実行→結果確認） | UI操作確認 |
| NFR-REL-001 | 信頼性 | 処理失敗時、システムが異常終了せずエラーメッセージを表示し、再実行可能であること。同一の音声ファイルを再実行した場合、全文テキストは実質的に同一の内容になること（faster-whisperのビームサーチ設定を固定し、決定論的な出力を目指す。ただし要約はLLMの非決定性により完全一致を保証しない。Round1レビューF-009対応：受入基準と整合させ、過度に厳密な「完全一致」要求を避ける） | 異常系テスト・再実行テスト |
| NFR-SEC-001 | セキュリティ | 外部有料APIキーを一切使用しない。生成データは外部送信されずローカルにのみ保存されること | コードレビュー・通信ログ確認 |
| NFR-MAINT-001 | 保守性 | ユニットテストカバレッジ80%以上 | カバレッジ計測 |
| NFR-PORT-001 | 移植性 | `requirements.txt` により依存関係を再現できること（Docker化はCould/Later） | 新規環境でのセットアップ確認 |
| NFR-EXT-001 | 拡張性（自由度） | 音声取得アダプタ（手動/Voicy URL）が設定またはコード上で明確に分離され、新しい取得方法を追加しやすい構造であること | 設計レビュー（SDD） |

## 11. セキュリティ・監査

- 認証・認可: 不要（自分専用・ローカルのみで完結、ネットワーク公開なし）
- 秘密情報: APIキー等の秘密情報は使用しない設計のため管理対象なし
- 監査ログ: `logs/app.log` に処理開始/完了/エラーを記録する（最大10MB、ローテーション1世代）
- インシデント対応: 該当なし（本番公開システムではないため）

### 運用・保守（監視の代替）

個人利用のローカルツールのため常時監視は行わないが、以下を最低限の運用保守要件とする。

| 項目 | 内容 |
|---|---|
| 監視の代替 | 処理失敗時はブラウザ画面とログの両方にエラー内容を表示する（FR-DATA-*の例外処理） |
| 既知障害への対応 | よくある障害（Ollama未起動、対応外ファイル形式等）は `README.md` のトラブルシューティング節に記載する |
| ロールバック | 個人ローカル環境のためGitでのバージョン管理のみで足りる（`git revert`で復旧） |
| ログ確認手順 | 利用者は `logs/app.log` を開いて直近のエラーメッセージを確認する |

## 14. リスク・変更管理

リスク一覧は `docs/risk_register.md` を参照（research_v2.mdのRISK-001〜005を正式化）。

### 変更管理プロセス
1. 要件変更が必要になった場合、変更理由をPROGRESS.mdに記録する
2. `docs/requirements_ledger.md` のトレーサビリティ列（設計ID/テストID）を逆引きし、影響を受けるFR-*/NFR-*・SDDセクション・TC-*を洗い出す（影響分析）
3. 影響を受ける全IDの状態を「要確認」に変更し、確認完了後に「Approved」へ戻す
4. 社長の承認を得てから変更を反映する

### エスカレーション基準
- Voicy利用規約に関する解釈の変更・疑義が生じた場合、即座に社長へエスカレーションし、FR-EXT-*の運用を停止する
