## 1. コード品質の制約

| ID | 制約 | 根拠 |
|---|---|---|
| C-CODE-001 | 1ファイル500行以下 | 可読性維持。超過時はモジュール分割 |
| C-CODE-002 | 1関数50行以下 | 単一責務原則。超過時は関数分割 |
| C-CODE-003 | 1クラス/1サービスモジュール200行以下 | 肥大化防止 |
| C-CODE-004 | ネスト3階層以下 | 可読性維持。超過時は早期リターンまたは関数抽出 |
| C-CODE-005 | 本番依存パッケージは`express`と`better-sqlite3`のみを基本とする | ADR-001（最小依存原則）。追加時はADRに理由を記載 |

---

## 2. セキュリティの制約

| ID | 制約 | 根拠 |
|---|---|---|
| C-SEC-001 | 外部APIキー・シークレットは本プロジェクトで使用しない（使用が必要になった場合、コード直書き禁止・環境変数経由のみ） | ADR-003（Ollamaは認証不要のローカルAPI） |
| C-SEC-002 | SQLインジェクション対策必須。全SQLクエリでbetter-sqlite3のプリペアドステートメント（`?`バインド）を使用 | OWASP Top 10 |
| C-SEC-003 | XSS対策必須。ブラウザ側でメモ本文・タイトルを表示する際は必ずエスケープする（`textContent`使用、`innerHTML`への生文字列挿入禁止） | OWASP Top 10 |
| C-SEC-004 | 入力検証必須。WebServer層（C-08）で全HTTP入力に型・長さチェックを適用（CC-04） | SRS 8.4入力バリデーション一覧 |
| C-SEC-005 | Webサーバーは`127.0.0.1`にのみバインドする。`0.0.0.0`でのバインド禁止 | ADR-004、NFR-SEC-001 |
| C-SEC-006 | 依存パッケージの既知脆弱性チェック必須（`npm audit`） | サプライチェーン攻撃防止 |

## 3. データ管理の制約

| ID | 制約 | 根拠 |
|---|---|---|
| C-DATA-001 | `data/*.db`ファイルへの直接手動編集禁止。NoteStore（C-01）経由のみで書き込む | データ整合性維持、CLAUDE.md PART D |
| C-DATA-002 | メモ削除は確認ダイアログ必須（HARNESS.md H1） | 誤削除防止 |
| C-DATA-003 | `PRAGMA journal_mode=WAL`を起動時に必ず設定する | NFR-REL-001 |
| C-DATA-004 | バックアップなしのスキーマ変更禁止。マイグレーション前に必ずバックアップを取得する | データ消失防止 |
| C-DATA-005 | ログ（`logs/app.log`）にメモ本文・質問文などの個人データを出力しない | プライバシー保護、CC-02 |
| C-DATA-006 | テストは本番`data/memory-assistant.db`を使用禁止。`tests/fixtures/`の専用テストDBを使用する | 本番データ保護 |

## 4. 開発プロセスの制約

| ID | 制約 | 根拠 |
|---|---|---|
| C-DEV-001 | コミットメッセージ形式: `type: description`（type = feat/fix/refactor/test/docs/chore） | 変更履歴の追跡容易性 |
| C-DEV-002 | テスト未実行でのマージ禁止。全テスト通過を確認後にコミットする | 品質ゲート |
| C-DEV-003 | 実装完了時にSD-02（受入条件検証）を実行し、スペックドリフトを報告する | harness/spec-drift.md |

## 5. AI（Claude Code）への制約

| ID | 制約 | 根拠 |
|---|---|---|
| C-AI-001 | SRS未記載機能の追加禁止。画像対応・クラウド同期・認証機能等（OUT OF SCOPE/DEFER）は追加しない | スコープクリープ防止、research/scope_table.md |
| C-AI-002 | テスト削除・改ざん禁止。テストが通らない場合は実装を修正する | FP再発防止 |
| C-AI-003 | 50往復超のセッション継続禁止。PROGRESS.mdに状態保存してセッション切替 | harness/session-mgmt.md |
| C-AI-004 | 「完了」宣言はSRS 14章のリリース判定基準（DoD）全項目チェック後のみ | 品質ゲート |
| C-AI-005 | 外部課金API・外部送信先の追加禁止。通信先はSQLite（ローカル）とlocalhost:11434（Ollama）のみ | ADR-001, ADR-003, NFR-SEC-001 |
| C-AI-006 | CONSTRAINTS.md自体の変更禁止。変更が必要な場合は人間に報告して承認を得る | 自己改変防止 |

## 6. 禁止ライブラリ・パターン

| ID | 制約 | 根拠 |
|---|---|---|
| C-BAN-001 | `eval()` / `exec()`（子プロセス実行含む動的コード実行）使用禁止 | コードインジェクションリスク |
| C-BAN-002 | ブラウザ側で`innerHTML`にユーザー入力を直接挿入禁止 | XSS防止（C-SEC-003） |
| C-BAN-003 | `console.log`によるメモ本文・質問文のデバッグ出力禁止 | プライバシー保護 |
| C-BAN-004 | 重量級フレームワーク（React/Vue等）・ビルドツールチェーンの追加禁止 | ADR-006（依存最小限） |
