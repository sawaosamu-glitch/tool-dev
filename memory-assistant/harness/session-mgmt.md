# セッション管理 — memory-assistant

nagame-devの50往復ルールをこのプロジェクトに適用する運用メモ。

## セッション終了手順（50往復到達時、またはフェーズ完了時）
1. 変更ファイルを`git add`して`git commit`（未完了作業も中間コミットする）
2. `PROGRESS.md`に以下を追記する: フェーズ・完了タスク・次のアクション・未解決問題・RYGステータス・ファイル変更一覧
3. 20〜40行程度に収め、詳細な議論の逐語録は書かない

## 新セッション開始手順
1. `CLAUDE.md` → `CONSTRAINTS.md` → `PROGRESS.md`の順に読む
2. `PROGRESS.md`の「次のアクション」「未解決問題」を確認してから作業再開する

## コンテキスト枯渇の兆候と対応
CONSTRAINTS.mdの制約を忘れる／同じ間違いを繰り返す／SRSの要件を無視する、のいずれかが起きたら即座に作業を停止し、PROGRESS.mdに「コンテキスト枯渇により緊急切替」と明記してセッションを切り替える。

## フェーズ別セッション数の目安
Phase 0〜5・7・8は各1〜2セッション、Phase 6（実装）はスコープに応じて2〜5セッション。2セッションで終わらないPhaseはスコープが大きすぎる兆候として見直しを検討する。
