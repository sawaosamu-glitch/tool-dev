# ロールバック計画

## RTO（復旧目標時間）: 5分以内（README.mdの復元手順に従う場合）
## RPO（復旧目標時点）: 直近のバックアップ世代（最大24時間前、起動時バックアップがあれば数分〜数時間前）

## ロールバック手順（データ破損・異常動作時）
1. アプリを終了する（Ctrl+C、またはプロセス終了）
2. README.md「データが壊れた・消えたときの復元手順」に従い、`data/*-wal`/`*-shm`を削除し`backups/`の最新世代を復元する
3. アプリを再起動し正常動作を確認する
4. それでも解消しない場合、1つ前のバックアップ世代で再試行する

## コードの巻き戻し（実装に起因する不具合の場合）
1. `git log`で問題発生前のコミットを特定する
2. `git revert`（または該当コミットへの`git checkout`）で該当バージョンに戻す
3. `npm install`で依存を再インストールし、`npm test`で正常動作を確認する

## ロールバック条件（以下のいずれか）
- メモの登録・検索・削除が正常に機能しない
- データが意図せず消失した
- `PRAGMA integrity_check`が継続的に失敗する
- セキュリティ上の懸念（外部への意図しない通信等）が発見された

## ロールバック不要の条件
- Ollamaの一時的な応答遅延・タイムアウト（自動的に検索ベースQAへフォールバックする設計のため）
- Ollama自体が未導入・停止している状態（Must要件には影響しない設計のため）
