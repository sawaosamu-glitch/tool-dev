## ADR-002: 日本語全文検索はFTS5 trigramトークナイザーを採用する

### 状態
承認

### 決定
SQLite FTS5の組み込みtrigramトークナイザーを日本語全文検索に採用し、形態素解析系の外部拡張（MeCab/Lindera/Vaporetto）は採用しない。

### 理由
- 追加依存・ネイティブビルド不要で導入できる（research/v1_A_tools.md A4）
- 個人メモ数百〜数千件規模ではFTS5単体で実用十分という技術的知見が複数のB評価ソースで一致（research/v1_C_arch.md C2）
- 形態素解析系拡張はStar数が少なく実績が限定的、依存最小限の方針と相性が悪い（research/v1_A_tools.md A5）

### 代替案
| 案 | メリット | デメリット | 不採用理由 |
|---|---|---|---|
| unicode61（FTS5既定） | 追加設定不要 | 日本語を分割できず検索が機能しない（公式ドキュメントで確認） | 日本語対応必須要件を満たさない |
| lindera-sqlite等の形態素解析拡張 | 検索精度が高い | ネイティブビルド・外部モデルファイル依存、実績が限定的 | 依存最小限の方針と衝突。将来、trigramの精度が不十分と判明した場合の代替候補としてadoption_stop_criteria.mdに記載 |

### 変更禁止レベル
L2-慎重（trigramの実運用精度がPhase 7 E2Eで不十分と判明した場合、代替案への切替を検討する）

### 実装前必須検証（Codex役レビュー指摘C-010、Escalate対応）
better-sqlite3がバンドルするSQLiteでtrigramトークナイザーが実際に利用可能かは、ドキュメント調査のみでは確認しきれていない（Escalate）。Phase 6実装着手の最初のタスクとして、以下を実行し成功を確認すること。
```sql
CREATE VIRTUAL TABLE _trigram_check USING fts5(x, tokenize='trigram');
```
失敗した場合はSQLiteのバージョン差異が原因である可能性が高く、その時点でbigram/unicode61＋LIKE併用など代替方式へ即座に切り替える（本ADRをL2として再改訂する）。

**検証結果（2026-08-31、Phase 6実装環境で実施）**: better-sqlite3 v13.0.3（同梱SQLite 3.53.4）で上記コマンドが成功し、trigramトークナイザーによる検索が正常動作することを確認済み。Escalateを解消し「確定」とする。

### 影響を受ける要件
FR-SYS-001, NFR-PERF-001, NFR-FUNC-001, RISK-001
