### E2E-01: メモ登録と全文検索（正常系1）

1. **前提条件**: アプリ起動済み、メモ0件の状態
2. **入力データ**: タイトル「買い物メモ」、本文「牛乳とパンとコーヒー豆を買う」、タグ「生活」
3. **実行手順**: メモ入力欄に入力→保存→検索ボックスに「コーヒー」と入力
4. **期待結果**: 保存直後に一覧先頭へ表示され、検索結果に当該メモがハイライト付きで表示される
5. **検証方法**: DB内`notes`テーブルに1件存在すること、検索APIレスポンスにメモIDが含まれることをアサート
6. **タイムアウト**: 5秒
7. **クリーンアップ**: テスト用DBファイルを削除

### E2E-02: 検索ベースQA（正常系2）

1. **前提条件**: メモが3件登録済み（うち1件が質問内容に関連）、Ollama未検出環境
2. **入力データ**: 質問文「コーヒー豆はどこで買うと言っていたか」
3. **実行手順**: 質問入力欄に入力→「相談する」を押す
4. **期待結果**: 関連メモの抜粋と出典（メモID・タイトル・日時）が表示され、生成AIは呼び出されない
5. **検証方法**: レスポンスの`mode`が`search`であること、`OllamaAdapter.generate`の呼び出し回数が0であることをアサート
6. **タイムアウト**: 5秒
7. **クリーンアップ**: テスト用DBファイルを削除

### E2E-03: 生成ベースQA（正常系3）

1. **前提条件**: メモが3件登録済み、Ollama起動中・`qwen3:4b`導入済み環境
2. **入力データ**: 質問文「コーヒー豆はどこで買うと言っていたか」
3. **実行手順**: 質問入力欄に入力→「相談する」を押す
4. **期待結果**: 生成AIによる要約回答が出典付きで表示される。応答時間10秒以内
5. **検証方法**: レスポンスの`mode`が`generated`であること、回答文に出典メモIDが含まれることをアサート
6. **タイムアウト**: 15秒
7. **クリーンアップ**: テスト用DBファイルを削除

### E2E-04: Ollama応答不可時のフォールバック（異常系1・外部障害）

1. **前提条件**: メモが3件登録済み、Ollamaプロセスを意図的に停止（未起動状態）またはタイムアウトするようモック
2. **入力データ**: 質問文「コーヒー豆はどこで買うと言っていたか」
3. **実行手順**: 起動時のOllama検出処理を実行→質問入力欄に入力→「相談する」を押す
4. **期待結果**: 生成AI利用不可の状態表示（FR-EXT-001）がされ、質問への回答は検索ベースQAとして表示される。エラーメッセージは利用者に露出しない
5. **検証方法**: レスポンスの`mode`が`search`であること、UIにエラースタックトレース等が表示されないことを確認
6. **タイムアウト**: 15秒（ヘルスチェック3秒＋質問応答10秒＋余裕2秒）
7. **クリーンアップ**: テスト用DBファイルを削除、Ollamaプロセスの状態を元に戻す

### E2E-05: 不正入力と根拠なき回答の拒否（異常系2）

1. **前提条件**: (a)(b)メモ0件の状態 (c)メモが1件「買い物メモ：牛乳とパンを買う」のみ登録済みの状態
2. **入力データ**: (a) 本文を空欄にしたメモ保存 (b) メモ0件の状態で質問文「猫の名前は？」を送信 (c) メモは1件存在するが、質問文「今日の天気は？」のようにメモ本文と全く関連しない質問を送信（＝検索結果が1件以上返る場合でも実質的に不一致なケース。E2E-05b）
3. **実行手順**: (a) 本文空のまま保存ボタン押下 (b)(c) 質問入力欄に入力→「相談する」を押す
4. **期待結果**: (a) 保存されずエラーメッセージ表示 (b)(c) いずれも「メモの中に関連情報が見つかりませんでした」と表示され、Ollamaは一切呼び出されない
5. **検証方法**: (a) DB内`notes`件数が0のまま (b)(c) `OllamaAdapter.generate`の呼び出し回数が0であること、`QAService.isRelevant()`が(b)(c)いずれもfalseを返すことをアサート（TC-UNIT-09b, TC-E2E-05b）
6. **タイムアウト**: 5秒
7. **クリーンアップ**: テスト用DBファイルを削除

### E2E-06: 本文上限境界値とプロセス強制終了からの復旧（境界値）

1. **前提条件**: アプリ起動済み
2. **入力データ**: ちょうど50,000文字の本文、タグ20個ちょうど
3. **実行手順**: 境界値のメモを保存→保存成功を確認→アプリプロセスをSIGKILLで強制終了→再起動
4. **期待結果**: 保存時点でエラーにならず正常保存される。再起動後、WALのマージにより強制終了直前までのメモ件数が1件も失われずに一致する。かつ起動時バックアップが`backups/`に生成されている
5. **検証方法**: 再起動後のメモ件数が強制終了前と一致すること、`backups/`配下に新規ファイルが存在することをアサート。50,001文字での保存は別途エラーになることも合わせて確認
6. **タイムアウト**: 20秒
7. **クリーンアップ**: テスト用DB・バックアップファイルを削除

### E2E-07: Ollamaモデル設定の切替（追加）

1. **前提条件**: `config.json`の`ollamaModel`が既定値`qwen3:4b`、Ollamaに`qwen3:8b`も導入済み環境
2. **入力データ**: `config.json`の`ollamaModel`を`qwen3:8b`に変更
3. **実行手順**: 設定ファイルを変更→アプリ再起動→質問応答を実行
4. **期待結果**: 生成ベースQAが`qwen3:8b`を使用して応答する（コード変更不要）
5. **検証方法**: OllamaAdapterへのリクエストペイロード中の`model`フィールドが`qwen3:8b`であることをアサート
6. **タイムアウト**: 15秒
7. **クリーンアップ**: `config.json`を既定値に戻す
